================================================================= PROYECTO: Sistema de
Gestión de Torneos ===================================================

REQUISITOS PREVIOS: - Windows - Microsoft Visual Studio 2022 - .NET 8
SDK - SQL Server - SQL Server Management Studio (SSMS)

  -----------------------------------------
  PASOS PARA CONFIGURAR LA BASE DE DATOS:
  -----------------------------------------

1.  CREACIÓN DE LA BASE DE DATOS:
    -   Abrir SQL Server Management Studio.
    -   Abrir el archivo “BD_Proyecto.sql”, ubicado en la raíz del
        proyecto.
    -   Ejecutar el script (F5).
    -   El script crea la base de datos “BD_Proyecto” y las tablas:
        Equipos, Jugadores y Usuarios.
    -   Ejecutar este script solamente cuando la base de datos todavía
        no exista.
    -   El script de creación no debe ejecutarse nuevamente sobre una
        base ya creada.
2.  CONFIGURACIÓN DE LA CADENA DE CONEXIÓN:
    -   Abrir la solución en Visual Studio.

    -   Abrir la clase “Conexion.cs”, ubicada en la carpeta “Datos”.

    -   La cadena de conexión incluida actualmente es:

        Server=.; Database=BD_Proyecto; Integrated Security=True;
        TrustServerCertificate=True;

    -   El valor “Server=.” hace referencia a la instancia
        predeterminada de SQL Server instalada en el mismo equipo donde
        se ejecuta la aplicación.

    -   El nombre del servidor o de la instancia depende de la
        instalación local de SQL Server.

    -   Si el equipo utiliza una instancia con nombre, reemplazar
        únicamente el valor de “Server” por el nombre correspondiente.
        Por ejemplo:

        Server=.;

    -   También puede utilizarse el nombre del servidor y la instancia
        que muestra SSMS al conectarse. No modificar los demás
        parámetros de la cadena de conexión.
3.  DATOS DE PRUEBA:
    -   Los scripts SQL incluidos crean la estructura de la base de
        datos, pero no insertan usuarios ni otros registros de prueba.
    -   Para iniciar sesión, debe existir previamente un usuario
        registrado en la tabla “Usuarios”.
    -   Si se proporcionan credenciales de prueba por separado,
        utilizarlas según los datos indicados por el equipo de
        desarrollo.
